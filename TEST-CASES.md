# Assisting mode — golden test cases

Not shipped to reps — internal checklist for verifying CLAUDE.md's "Assisting mode" before rollout. Use fictional reps and labels only. The cases assume one project whose `PROFILE.md` has two rep sections: Sam (registry id `rep-sam`, login label `sam`) and Lee (`rep-lee`, label `lee`), each with their own counties.

1. **Rep named.** Ask: "find leads for Lee." Expect: "For Lee:" at the top; every `my_sources`, `lead_board` and `lead_scan` call carries Lee's `rep_id`; every QuickBase call except `check_configuration` carries `profile` = `lee`; no call goes out without both.
2. **County that belongs to one rep.** Ask, with no name: "what's new in [a county only Sam has]?" Expect: Claude says in one line it's Sam's county and the request is for Sam, then runs it with Sam's pair.
3. **Ambiguous request.** Ask: "pull up my pipeline." Expect: one question, "For Sam or Lee?", and no tool call before the answer. The answer "Lee" is then used for every call.
4. **Both.** Ask: "what's new for both of them?" Expect: the scan runs once per rep, one rep at a time, each with that rep's pair; two separate headed sections ("For Sam:", "For Lee:"); no merged list, count or total.
5. **Switch by name mid-conversation.** Work a lead for Sam, then say "now Lee's pipeline." Expect: the next calls use Lee's `rep_id` and `profile`, and nothing from Sam's list or board appears under Lee.
6. **Pair never mixed.** Across a Sam request, a Lee request and a subagent hand-off, inspect every call. Expect: `rep_id` and `profile` always come from the same section, and a subagent brief names one rep with both values.
7. **Saved files go in the rep's folder.** Run a scan for Sam, then for Lee. Expect: `sam/lead-board.xlsx` and `lee/lead-board.xlsx` (or `.csv`); neither run reads or writes the other's board, and no board lands at the top level. `PROFILE.md` and the `Bliss Tools` folder stay at the top level.
8. **Other rep's county is a switch.** Working for Sam, ask for an email on a lead in a county only Lee has. Expect: one line saying that county is Lee's and Claude is switching to Lee; the draft is Lee's, in Lee's name and voice, with the QuickBase check redone under `lee`; no out-of-territory stop.
9. **Neither rep's county is a stop.** Ask for an email on a lead in a county neither rep has. Expect: the stop, worded "isn't in Sam's or Lee's counties", with no rep's own wording ("your counties").
10. **Setup pairing mismatch stops.** In first-run setup, answer "assist"; the lookup under label `lee` returns Sam. Expect: setup stops and names the label and the rep that disagree; no profile is saved.
11. **Setup fails closed.** Run setup three times: `list_reps` empty; `check_configuration` lists no logins; a lookup under a label finds no active rep. Expect each to stop with a line to ask the trainer, with no lookup under the helper's own login and no name search.
12. **Setup flow.** Answer "assist". Expect: `list_reps` and a confirmation of the reps; `check_configuration` and a pairing question; `my_sources` with each rep's `rep_id` and the "Who am I" lookup with each rep's `profile`; all reps in one confirmation message; one saved profile with a section per rep (name, QuickBase name, registry id, login label, counties).
13. **Profile refresh keeps all sections.** Run "refresh my profile" after Sam gained a county. Expect: Sam's Territory/Counties rewritten from Sam's calls; Lee's section re-read from Lee's calls; both sections, both registry ids and both labels still there; Focus Counties untouched; reports under a heading per rep.
14. **Refresh and the rep list.** `list_reps` now shows a third rep. Expect: Claude says so and offers to add that rep, and changes nothing else. Then a section's rep is missing from `list_reps`: Claude says so and leaves the section in place.
15. **Refresh fails closed.** Lee's `my_sources` call is rejected during a refresh. Expect: Lee's section unchanged, one line naming Lee, and Sam's section refreshed normally.
16. **"Pick one" replies.** A call comes back "You assist <names>. Pass rep_id to pick one." or "Two QuickBase logins are configured: <labels>. Pass profile to pick one." Expect: `PROFILE.md` is read again and the call retried with the current rep's value from its section; no name or label is chosen from the reply. In a project with no rep sections, nothing is picked and Claude says the project isn't set up for assisting.
17. **Wrong value.** A call comes back "rep_id must be one of the reps you assist: …". Expect: stop with one line; no name from that list is tried.
18. **Normal rep unaffected.** First-run setup, answer "for yourself". Expect: the same steps as before, no `list_reps` or `check_configuration` call, a profile with no rep sections and no `Mode:` line, no `rep_id` or `profile` on any call, no rep question on any request, check-ins set up as usual. The only new thing the rep sees is the one yes/no question.
19. **Check-ins cover each rep.** After assisting setup, `list_scheduled_tasks` shows the five standard task ids with no label suffix. Run the daily run. Expect: "Good morning. Here's the daily run.", then a "For Sam:" block and a "For Lee:" block, each from that rep's own calls; nothing merged. "Check my setup" reports nothing missing and checks each rep's profile and login, naming the rep in any problem.
20. **Draft voice and sign-off.** Ask for an intro email for Lee. Expect: Lee's name in the heading, written in Lee's voice, signed with Lee's name and contact, shown as a draft; a Voice question, if asked, is about how Lee writes and is saved on Lee's section only.
21. **Mail is the helper's.** Ask Claude to check for earlier emails with a buyer. Expect: Claude says the look-up reads the helper's own mailbox, not a rep's, and doesn't present the result as Sam's or Lee's.
22. **Talking to the helper.** Run any tool. Expect: the helper is never greeted by a rep's first name; every reply with rep data starts with "For [Rep]:" or has the rep's name as its heading; reps are named in the third person.
23. **Lead numbers.** Run Lead Finder for Sam, then for Lee, then say "research #2". Expect: Claude asks "For Sam or Lee?" (or follows the continuation rule if Lee's list was just discussed), and never opens #2 from the wrong list.
